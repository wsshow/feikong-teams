# 数据存储与首次升级

应用使用纯 Go 的 `modernc.org/sqlite`，数据库位于应用目录的 `data/fkteams.db`。默认应用目录是 `~/.fkteams`，可用 `FEIKONG_APP_DIR` 覆盖。

| 数据 | 保存位置 |
| --- | --- |
| 会话信息、主会话及成员聊天记录、待执行消息、会话待办 | SQLite |
| 长期记忆、分享授权、定时任务定义与状态、JavaScript 扩展状态 | SQLite |
| 上传附件、队列图片、工具大结果、调度报告、工作区文件 | 原文件目录 |
| 配置、技能、提示词、日志、CLI 输入历史、缓存 | 原文件目录 |

首次运行新版前，退出使用同一应用目录的旧版进程。新版会持有目录锁，避免多个新版实例同时使用同一份数据；旧版程序不认识此锁。

## Web 升级

检测到旧数据时，Web 模式先展示一次性升级弹窗，暂停聊天、消息通道和定时任务。点击“备份并开始升级”后，后台依次执行：

1. 复制 `sessions/`、`scheduler/`、`share/`、`javascript/state/`、`workspace/memory/` 到 `backups/storage-时间-随机标识/`。配置和登录凭据文件不在自动备份范围内。
2. 核对备份文件 SHA-256，写入 `manifest.json`，验证业务格式及队列附件引用。
3. 在一个 SQLite 事务内导入结构化数据和长期记忆，逐条回读核对，再执行数据库完整性检查。
4. 将完成标记与业务数据一起提交，关闭维护入口并启动正常服务。

页面显示阶段进度和备份位置。刷新、断线或关闭页面不会取消任务；重新打开页面可继续查看进度。数据提交和正常服务就绪后，点击“开始使用”。完成标记持久化保存，后续启动直接进入应用。

若升级失败，界面显示原因并允许重试；不会启动业务，也不会把失败任务标记为完成。修复磁盘空间、权限、损坏文件等问题后重试。程序在事务提交前退出时，未完成导入会回滚；重启后重新备份和迁移。已经创建的备份不会自动删除。

旧版结构化文件原样保留，但升级后的运行数据以数据库为准。不要通过编辑旧 JSON、JSONL 或记忆 Markdown 修改业务数据。长期记忆在侧栏“记忆”页面管理，关闭自动记忆提取时仍可手动管理。

## CLI 与纯 API

CLI 查询、交互会话、`session list` 和 `serve` 在业务启动前自动执行同一迁移用例，不需要浏览器。升级日志及备份位置写入标准错误；失败返回错误并停止启动。其他不读取业务数据的命令（例如生成配置、查看版本）不触发迁移。

Web 维护期间可调用以下接口，沿用正常登录认证和跨域限制：

- `GET /api/fkteams/storage/migration`：返回 `{ migration: { state, stage, completed, total, backup_path, error }, ready }`，包裹在标准 API 响应的 `data` 中。
- `POST /api/fkteams/storage/migration`：开始或重试升级。重复请求复用当前任务，请求断开不取消后台任务。

`state` 为 `pending`、`running`、`failed`、`completed`；`stage` 为 `backup`、`import`、`verify`、`completed`。进度数值是当前阶段的完成数量。维护期间 `ready=false`，业务接口返回 503；正常服务启动后 GET 返回 `ready=true` 和已提交的备份位置，POST 升级入口不再开放。纯 API 模式在开始监听之前已自动完成升级。

## 备份与恢复

SQLite 使用 WAL 模式。常规完整备份应在应用完全退出后复制整个应用目录，包含 `data/` 及附件、报告、工作区；不要在运行时只复制 `fkteams.db` 而遗漏 WAL。恢复到另一位置时，将完整目录放到目标位置并设置 `FEIKONG_APP_DIR`。

首次升级的自动备份保存的是升级前业务目录，不包含配置，也不包含升级后的修改。需要回到旧版时，先完全退出新版，在独立应用目录恢复原配置及备份中的业务目录，再用旧版启动；不要让旧版与新版同时写入同一目录。保留当前数据库和文件，避免覆盖升级后新增的数据。
