# 个人助手

助手入口直接接收问题、资料和交办，按任务使用工具、技能和相关历史。普通问答不建立任务，也不要求用户选择执行模式。

## 能力与协作

个人助手通过标准 AgentKit 成员工具调用已启用的团队成员，沿用工具权限、审批、流式事件及历史链路。常规工作直接完成，独立复杂子任务按需委派，并由助手检查和整合结果。`assistant_capabilities` 返回本次运行实际接入的成员和调用工具；配置失败的成员标为不可用，不影响助手的基础能力。配置更新后按现有机制重建 Runner。

技能仍使用现有按需加载机制；外部服务只能通过实际配置的工具或成员接入，不把未连接的功能描述为可用。

## 记忆与任务

长期偏好和可复用经验由助手主动维护，见[主动记忆](memory.md)。需要多步或跨回合完成的交办通过 `task_save` 保存独立任务；`task_list` 查询未完成事项或已完成结果。

任务包含目标、完成标准、来源会话、进展、下一步、结果和可选的调度 ID。创建使用稳定 key 防止重试重复建单；更新要求 ID 和版本，冲突时重新读取。所有状态写入原子持久化，失败不确认成功。

- `pending`：已记录，尚未推进。
- `in_progress`：目标正在推进，不表示当前有后台进程。
- `waiting_user`：等待用户信息或决定，必须记录下一步。
- `waiting_time`：等待已创建的定时任务，必须关联调度 ID。
- `paused`：用户暂停，保留进展。
- `completed`：已交付并记录验证后的结果。
- `failed`：执行受阻，保留原因和继续处理的办法。
- `cancelled`：用户取消。

重启或切换话题后，助手通过任务记录、来源会话与实际环境核对进展，再继续工作。恢复记录不会自动重放已执行的命令或对外操作。暂停、取消目标记录不等于停止实际调度；助手还必须调用相应调度操作。

任务结果可以记录真实交付物的位置与链接，读取记录本身不会访问其中的路径。所有实际文件操作仍通过原有工作区工具与权限检查。
