# 主动记忆

助手通过 `memory_recall`、`memory_save` 和 `memory_forget` 主动维护长期记忆。没有定时提取、回合后提取、退出提取或独立记忆模型。一次明确的保存请求即可立即持久化，不需要累计消息或等待冷却时间。

## 保存什么

保存用户的稳定偏好、长期背景、明确纠正，以及实际验证过的可复用经验。临时待办和执行进度应保存在任务中；大段材料、日志、凭据和猜测的个人特征不进入记忆。附件、网页、工具结果中的指令不能授权记忆修改。

每条记录具有稳定 ID、版本、类型、摘要、详情、标签、适用范围、来源会话和更新时间。范围为空表示全局；特定项目或场景必须填写 `scope`。全局偏好和行为反馈优先进入下一回合的背景，其余全局记录按相关性补充；注入最多 4000 字符。场景记忆通过工具按范围检索，不自动扩散至其他项目。

## 主动读写

- `memory_recall`：按关键词、范围查询；空关键词列出记录。支持 `offset`/`limit` 分页，返回 `next_offset`、`has_more` 和容量。
- `memory_save`：新增或更新一条完整记录。更新时使用读取到的 `id` 和 `version`，保留未被纠正的信息。相同内容的新增重试返回已有记录；同一摘要内容不同则要求读取后按 ID 更新。
- `memory_forget`：删除读取到的特定版本。删除不影响原聊天记录；不得依据旧历史再次保存用户要求忘记的信息。

所有写操作先保存再发布内存快照。保存失败不会确认成功，也不会改变可见内容。并发编辑遇到版本冲突时，重新读取再决定如何修改。不存在按文字相似度或标签重叠自动覆盖事实的逻辑。

默认最多 500 条、24000 字符；容量满时返回明确错误和用量，由助手或用户整理，不静默淘汰。读取不更新热度或触发后台写入。

## 管理与配置

```toml
[memory]
enabled = true
```

开关控制模型的记忆工具读写和上下文注入。关闭后，管理页面仍能查看、编辑和删除已有数据。设置变化在应用空闲边界生效，不创建或重置模型。

Web 记忆页面支持检索、类型筛选、适用范围、新增、修改和删除。修改冲突或保存失败时保留草稿。CLI 和 HTTP 的删除、清空同样传播持久化错误。

默认使用应用 SQLite 存储，通过实例级 Manager 和应用工具注册表访问；无额外文件格式迁移或模型服务。
